# 교재 문장 규칙

교재를 읽는 사람은 **신입 네트워크 엔지니어**다. 처음 보는 개념을 붙잡고,
터미널을 옆에 띄워 두고, 막히면 되돌아와 다시 읽는다. 그 사람이 빨리 찾고
정확히 이해하도록 쓴다. 읽는 재미나 저자의 목소리는 목표가 아니다.

## 1. 문체 — 교육생이 읽는 글은 존댓말

교육생이 보는 문서(교재 · 과제 · 퀴즈 해설)는 **`~합니다`** 로 쓴다.

> 스위치는 목적지 MAC 을 표에서 찾아 그 포트로만 보냅니다.

무엇을 하라고 시키는 문장은 **`~하세요` · `~해 주세요`** 로 쓴다.

> 터미널을 두 개 열어 주세요.

교재 앞머리(제목 · 도입 · 학습 목표)와 절 제목은 이름표에 가까우므로 짧게 둔다.
`## 3. 직접 만든다` 를 `직접 만듭니다` 로 고치지 않는다.

강사용 해설(`answers.md.j2`)과 코드 주석은 대상이 다르므로 평서형(`~한다`)을 쓴다.

> 예전에는 설명을 평서형(`~한다`)으로 썼다. 한 화면에 `~한다` 가 스무 번씩 이어져
> 읽는 사람이 밀려난다는 지적을 받아 바꿨다. 아직 바뀌지 않은 모듈은
> `make style` 의 `평서형` 칸이 몇 문장 남았는지 세어 준다.

## 2. 인용구(`>`)는 두 종류뿐

한 화면에 같은 모양이 다섯 가지 일을 하면 아무 뜻도 못 가진다.
접두어로 종류를 밝히고, **한 절에 하나까지만** 쓴다.

| 형태 | 언제 |
|---|---|
| `> 실무 —` | 현장에서 실제로 이렇게 한다는 정보 |
| `> 주의 —` | 모르고 지나가면 사고가 나는 것 |

여담·배경·"앞으로 배울 것" 은 인용구로 만들지 않는다. 본문에 한 문장으로
넣거나, 그 자리에 필요 없으면 지운다.

## 3. 굵게는 단락당 하나까지

용어를 처음 정의할 때, 또는 판정 기준 하나를 짚을 때만 쓴다.
다 굵으면 아무것도 굵지 않다.

## 4. 제목을 되풀이하지 않는다

`### 2.1 L1 — 링크가 살아 있는가` 바로 아래에 "링크가 살아 있다는 것은…"
으로 시작하지 않는다. 제목이 이미 한 말이다. 바로 내용으로 들어간다.

## 5. 자료를 논평하지 않는다

이런 문장은 정보가 아니라 정보에 대한 감상이다. 지운다.

- "신입이 가장 자주 건너뛰는 층이기도 합니다"
- "그 순간이 L3 를 배우는 지점입니다"
- "이 실습이 M1 의 핵심입니다"

정보가 섞여 있으면 정보만 남긴다. "30분을 버린다" 는 남기고, "여기서
갈리는데" 는 뺀다.

## 6. 한 단락은 한 생각, 세 문장까지

넘으면 자른다. 목록이나 표로 바꿀 수 있으면 그렇게 한다.

## 7. 사실은 표와 명령이 지고, 산문은 잇는다

표로 쓸 수 있는 것을 문장으로 늘어놓지 않는다. 산문은 표와 표 사이를
이어 주고, 왜 그것을 보는지만 말한다.

## 8. 표는 찾아보는 것에만 쓴다

표는 **훑어서 한 칸을 찾는** 물건이다. 그 목적이 아니면 표로 만들지 않는다.

| 표로 만든다 | 표로 만들지 않는다 |
|---|---|
| 3열 이상이고 칸끼리 비교된다 | 2열에 2행 이하 |
| 나중에 다시 찾아볼 목록 (명령 대응, 점검 순서) | 한 번 읽고 마는 설명 |
| 항목마다 같은 종류의 값이 채워진다 | 문장을 두 도막 낸 것뿐 |

두 줄짜리 표는 거의 항상 목록이나 한 문장이 낫다. 표는 눈을 멈추게 하는데,
멈출 값어치가 없으면 읽는 속도만 깎는다.

비율에는 기준을 두지 않는다. M10 처럼 13행짜리 명령표와 9단계 점검표가 곧
본문인 문서는 30% 가 나와도 맞다. 날카로운 규칙은 위의 **2열 2행 이하 금지**
하나뿐이고, 나머지는 "이 표를 나중에 다시 찾아볼 것인가" 로 판단한다.

## 9. em 대시(—)는 한 문장에 하나까지

제목의 부제, 표의 빈칸, 그리고 한 문장에 한 번. 그 이상은 쉼표나
마침표로 바꾼다.

## 10. 조사는 변수 뒤에 바로 붙이지 않는다

`{{ '{{ ip.pc2 }}' }}` 같은 값 뒤에 `은/는·이/가·을/를` 을 바로 붙이면
읽는 값에 따라 틀린다. 앞에 고정 명사를 둔다.

- 나쁨: `{{ '{{ next.id }}' }}가 열립니다`
- 좋음: `{{ '{{ next.id }}' }} 모듈이 열립니다`

## 11. 지키는지 재는 법

```
make style      # 퀴즈 문항 수 · 굵게 밀도 · 인용구 비율을 센다 (make check 도 함께 돈다)
```

기준은 아래와 같다. 넘으면 그 모듈을 다시 본다.
문장 밀도는 사람이 읽고 판단할 몫이라 재기만 한다. 아래 둘은 세면 답이 나오므로
검사가 막는다.

**퀴즈 문항 수** — 통과 기준이 100 점이라 한 문항이 곧 재시험이고,
스물이 되면 아는 사람도 다섯 번씩 다시 푼다.

**모양이 정답을 가리키는 문항** — 선택지를 읽지 않고도 고를 수 있는 표시들이다.
넷 다 교육생이 실제로 쓰는 요령이므로, 하나라도 남으면 그 문항은 개념을 묻지 못한다.

- 대시(`—`) 뒤 근거절이 일부 선택지에만 붙어 있다
- 굵게가 정답에만 붙어 있다
- 정답만 다른 것보다 눈에 띄게 길다
- `항상` · `전부` 같은 단정이 오답에만 있다

**평서형 문장 수** — 존댓말로 바꾸는 일은 모듈을 다시 쓸 때 함께 한다.
한 번에 다 바꾸면 어색한 문장이 섞여도 아무도 못 잡는다. 그래서 막지 않고 세기만 하고,
`tools/tone.py` 로 초벌을 뽑은 뒤 사람이 훑는다.

```
python3 tools/tone.py modules/m04-ospf/README.md.j2 '## 1. 이 모듈에서 만들 것'
```

**과제가 앞 모듈을 가리키는 줄** — 과제는 그 모듈 안에서 끝나야 한다.
앞 모듈에서 만든 캡처·점검표·표를 가져오라고 하면, 늦게 합류했거나 그 파일을
잃은 사람은 손도 못 댄다. 앞을 가리키는 것(`M4 로 넘어가도 됩니다`)은 의존이
아니므로 놔둔다. 캡스톤(M10)만 예외다 — 전 과정을 모아 보는 자리이기 때문이고,
누적 범위를 진단하는 것이 목적인 중간 점검은 `BACK_OK` 에 이유와 함께 적는다.

넷을 피하는 방법은 하나다 — **네 선택지를 같은 모양으로 쓴다.**
근거절을 붙이면 넷 다 붙이고, 길이를 비슷하게 맞추고, 용어 배지(`4-tuple`)나
교재 인용(`M6 감별표의 ②`)을 정답에만 달지 않는다.
틀린 단정 자체가 시험하려는 오해일 때는 예외로 두되,
`tools/check-style.py` 의 `SHAPE_OK` 에 이유와 함께 적는다.

| 지표 | 기준 |
|---|---|
| 모듈당 퀴즈 문항 | 12 개 이하 (검사가 막는다) |
| 모양이 정답을 가리키는 문항 | 0 개 (검사가 막는다) |
| 과제가 앞 모듈을 가리키는 줄 | 0 개 (검사가 막는다) |
| 문장당 굵게 | 0.35 개 이하 |
| 100줄당 인용구 | 8줄 이하 |
| 접두어 없는 인용구 | 0 개 |
| 표가 차지하는 줄 | 재기만 한다 (참고값) |
| 2열 2행 이하 표 | 0 개 |
| 평서형(`~한다`)으로 끝나는 문장 | 재기만 한다 (0 이 목표) |

## 12. 구성도의 장비는 프리셋을 따른다

`r1` 은 랩 지도에서도, 교재의 작은 구성도에서도, 순서도의 기둥 머리에서도
**같은 그림 · 같은 색**이어야 한다. 다르면 교육생은 다른 장비로 읽는다.

모양과 색은 `tools/devices.py` 한 곳에서 정한다. 여기를 고치면 화면 · 오프라인
교재 · `.drawio` 내보내기가 함께 바뀐다. 개별 구성도에 색을 적지 않는다.

| 역할 | 그림 | 이름 규칙 |
|---|---|---|
| host | PC | `pc1` · `pc2` |
| switch | 스위치 | `sw1` · `sw2` |
| router | 라우터 | `r1` ~ `r4` · `라우터` |
| server | 서버 | `web` · `ftp` · `dns` |
| edge | 방화벽 | `edge` · `fw` |
| cloud | 구름 | `inet` · `인터넷` |

이름이 규칙에 걸리지 않으면(예: `서버망 DHCP`) 장비가 아니라 개념 상자로 그린다.
장비인데 이름이 다르면 구성도에 `shapes: {이름: router}` 로 지정한다.

**링크에는 포트와 주소를 적는다.** 어느 포트에 무엇이 붙어 있는지 그림이 말해
주지 않으면, 교육생은 장애 앞에서 어디를 볼지 모른다. 실제로 이어진 두 장비를
잇는 선이면 `a`·`b` 로 짝을 적고 `ends` 에 양 끝을 넣는다 — 표기는 랩 지도와
같은 `포트 .끝자리` 이고, `end('r1', 'r2')` 가 설계에서 뽑아 준다.

```yaml
links:
  - { a: r1, b: r2, label: "{{ p2p['r1-r2'].cidr }}",
      ends: ["{{ end('r1', 'r2') }}", "{{ end('r2', 'r1') }}"] }
```

짝을 적지 않으면 이웃 열끼리 모두 잇는다 — 링크마다 대역이 다르면 그 방식으로는
적을 수 없으므로 짝을 적는다. 물리적으로 직접 이어져 있지 않은 사이(경로를 줄여
그린 그림)에는 포트를 적지 않는다. 없는 연결을 있다고 말하기 때문이다.

색은 실루엣을 거들 뿐이다 — 흑백으로 인쇄해도, 색약이어도 라우터와 PC 가
구분돼야 하므로 모양이 먼저다.

## 13. 목차

교재 맨 위의 목차는 `tools/mdtoc.py` 가 `##` 제목에서 자동으로 만든다.
손으로 적지 않는다. 절 제목을 고치면 목차도 따라간다.
