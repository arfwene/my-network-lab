## 교육생을 받으려면

1. **[관리] → [계정 관리]** 에서 계정을 만듭니다. 랩 번호를 배정합니다.
2. 임시 비밀번호가 **한 번만** 보입니다. 그 자리에서 전달하세요.
3. 교육생이 첫 로그인하면 비밀번호를 강제로 바꿉니다.
4. 그다음 화면이 알아서 안내합니다 — 랩 생성 → 접속 키 등록 → 교재.

관리자가 손댈 것은 1번뿐입니다. 랩 생성도, 점프 계정도, SSH 키 반영도
전부 자동입니다.

시험용 계정 정리:

```
[관리] → [계정 관리] → trainee1 · trainee2 → 삭제
```

랩도 지우려면 각 랩 화면에서 [랩 삭제] 를 누르면 됩니다.

## 오늘 확인한 것

**모듈 11개 전부** — 적용 · 퀴즈 · 검증을 교육생 계정으로 끝까지 돌렸습니다.

M07 의 검사 5개는 교육생이 과제에서 만들어야 할 pcap 파일을 보는 것이라
자동 실행에서는 통과하지 않습니다. 정상입니다.

**다중 랩 · 다중 교육생**

- VMID · 브리지 이름 · 관리망 대역이 랩 6개까지 겹치지 않는 것을 계산으로 확인
- lab1 · lab2 를 동시에 만들어 VM 26대가 함께 도는 것을 확인
- 같은 랩에 두 작업을 걸면 **409** 로 막힘
- `trainee1` 이 lab2 를 건드리려 하면 **403**
- SSH 도 막힘 — `trainee1` 이 lab2 노드로 가면 `stdio forwarding failed`
- 점프 호스트에서 셸을 얻으려 하면 `This account is currently not available`

## 오늘 고친 것

랩이 실제로 동작하지 않던 것들입니다. 전부 이 서버에서 재현하고 고쳤습니다.

| 무엇 | 증상 |
|---|---|
| FRR 줄 끝 주석 | M3 정적 라우팅이 **한 번도 동작한 적이 없었음** |
| netplan 이 스위치 포트를 회수 | 브리지에 포트 0개인데 서비스는 "성공" |
| 초기화가 링크로컬을 삭제 | OSPFv3 가 이웃을 못 만듦 (IPv4 는 멀쩡) |
| rp_filter | traceroute 중간 홉이 `*` 로만 나옴 |
| nginx add_header 상속 | `X-Lab-Node` 헤더가 빠져 검사 3개가 실패 |
| edge 방화벽 input | **공인 IP 의 22번이 인터넷에 열려 있었음** |
| OSPF 수렴 전 판정 | 멀쩡한 랩이 검증에서 떨어짐 |
| 두 번째 [이 모듈 적용] | 랩이 주소를 잃음 |
| 새 랩의 스위치 기동 순서 | 두 번째 랩부터 적용 실패 |
| 랩 생성이 부팅을 안 기다림 | 바로 적용하면 UNREACHABLE |
| FRR 시작 제한 | 모듈을 연달아 적용하면 4번째가 거부 |

## 문제가 생기면

**콘솔이 이상하다** — [관리] 메뉴의 "지금 도는 코드" 가 최신 커밋인지 봅니다.
아니면 재시작이 안 된 것입니다.

```
ssh labtest 'cd ~/my-network-lab && git pull && sudo systemctl restart my-network-lab'
```

**랩이 이상하다** — 해당 랩 화면에서 [이 모듈 적용]. 1분이면 그 모듈의
시작 상태로 돌아갑니다. 그래도 이상하면 [랩 삭제] → [랩 생성].

**전체 점검** — [관리] → [설치 상태] → [다시 검사].

**랩이 여러 개일 때 가장 조심할 것 — 디스크.** `local-lvm` 은 thin pool 이라
랩 하나가 104GiB 를 약속하고 실제로는 25GiB 안팎만 씁니다. 풀이 꽉 차면
그 랩만이 아니라 **같은 풀 위의 모든 랩이 함께 멈춥니다.** [랩 생성] 이
여유 공간을 먼저 보고 부족하면 멈추도록 해 뒀지만, 한 번씩 [설치 상태]
에서 여유 GiB 를 봐 주세요. 랩 6개까지가 안전선입니다 (`docs/DECISIONS.md` 3번).
